# 办公设备易采买 —— 答案输出与渲染规则

交付任何办公设备/耗材比价结论前，必须按本文件逐项核对。

---

## 0. 处理流程（先做什么）

1. 调用 `uv run scripts/main.py search --source=0 --keyword='{关键词}'`。
2. **先读返回 JSON 顶层的 `matched` 字段**：
   - `matched: true` → 云端已命中映射表，`queries` 中已包含主设备 + 耗材/配件结果，直接渲染。
   - `matched: false` → 执行第 1 节的**宿主 AI 智能匹配兜底**，再合并渲染。
3. 对要写进表格的每一行商品，调用 `detail` 获取真实购买链接与专票/质保信息。
4. 按第 2~4 节选择对应表格模板输出，并附第 6 节数据来源声明。

---

## 1. 🤖 客户端宿主 AI 智能匹配兜底逻辑

当 `search` 返回的 JSON 顶层包含 `"matched": false`（云端静态字典未命中该设备的耗材/配件）时，按以下三步处理：

### 1.1 AI 推理耗材/配件型号

利用大模型自身知识库，推理该设备对应的**标准耗材或扩展配件型号**。推理依据优先级：

| 设备类型 | 推理目标 | 示例 |
| :--- | :--- | :--- |
| 打印机 / 一体机 / 复合机 | 碳粉盒、硒鼓、墨盒、色带、废粉盒型号 | 「奔图 P2200」→ 耗材 `PD-201 碳粉盒` |
| 服务器 | ECC 内存规格、硬盘接口尺寸、托架、电源 | 「浪潮 NF5280M5」→ `DDR4 ECC RDIMM 32G` + `2.5寸 SAS 硬盘托架` |
| 台式机 / 微型机 / 笔记本 | 内存条类型（UDIMM / SO-DIMM）、M.2 规格 | 「联想 M730q」→ `DDR4 SO-DIMM 笔记本内存 16G` |
| 显示器 | VESA 孔距、原装支架、视频线规格 | 「戴尔 U2422H」→ `VESA 100x100 支架` |
| 标签 / 票据打印机 | 纸卷规格（宽×直径/内径）、碳带类型 | 「佳博 GP-3120TU」→ `热敏标签纸 40x30 卷芯25mm` |

推理时必须遵守：
- **不确定就说不确定**。无法可靠推导型号时，明确告知"该设备耗材型号无法确定，建议以机身标签/说明书型号为准"，不得编造型号。
- **区分原装与兼容**。二次查询时至少各查一次。
- **不把主设备结果与耗材结果混为一行**。

### 1.2 二次查询

```shell
uv run scripts/main.py search --source=0 --keyword='PD-201 碳粉盒 原装'
uv run scripts/main.py search --source=0 --keyword='PD-201 碳粉盒 适用'
```

云端首次返回的 JSON 中还有 `hint` 字段，按其中提示执行即可。

### 1.3 合并展示

将**云端第一次返回的主设备比价结果**与**第二次查询到的耗材/配件比价结果**整合为两份表格：
主设备表格 + 「配套耗材/扩展配件推荐」区块，并在区块前注明
"⚠️ 该设备的耗材型号由 AI 推理得出，下单前请核对机身标签"。

> 补充：也可调用 `uv run scripts/main.py mapping --device='{型号}'` 主动查询云端映射表，
> 命中则直接使用其返回的 `original_keyword` / `compatible_keyword` / `accessory_keywords`。

## 2. 📊 结构化 Markdown 输出格式

### 2.1 设备与整机类（电脑 / 服务器 / 打印机 / 显示器 / 人体工学椅）

| 平台 | 店铺类型 | 价格 | 专票/质保 | 核心特征/备注 | 购买链接 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **京东** | 自营官方 | ¥1,099 | 支持专票 / 1年上门 | 次日达 / 晒单送配件 | [查看详情](url) |
| **天猫** | 品牌旗舰店 | ¥1,049 | 支持专票 / 1年联保 | 赠电缆 / 现货 | [查看详情](url) |

字段取值规则：
- **平台**：取 `platform`（由 `source` 映射：1→淘宝/天猫，2→京东，3→拼多多…）。
- **店铺类型**：从 `shopName` 判断——含"自营""官方旗舰店""专卖店""专营店"等字样时按实际标注，否则写"第三方卖家"。
- **价格**：取 `actualPrice`（券后到手参考价）。若 `coupon_desc` 非空，在该行备注补「原价 ¥X，券后 ¥Y」。
- **专票/质保**：只能引用 `detail` 返回的 `data.invoice.supported` 与 `data.warranty.text`。
  - `supported: true` → "支持专票"；`false` → "不支持专票"；`null` → "专票未标注"。
  - 质保字段为"未标注"时，表格中照写"质保未标注"，不得自行推断 1 年/3 年。

💡 **配套耗材/扩展配件推荐**（`matched: true` 时来自 `queries` 中 `kind` 为
`original` / `compatible` / `accessory` 的查询结果；`matched: false` 时来自 AI 兜底二次查询）：

* **原装耗材**：`[型号]` 全网最低 ¥XX（店铺 / 平台）
* **第三方兼容**：`[品牌/型号]` 全网最低 ¥XX（店铺 / 平台）
* **扩展配件**：`[配件名]` 全网最低 ¥XX（店铺 / 平台）

推荐区块必须以"仅列出本次查询到的记录，未覆盖渠道不代表无更低价格"收口。

### 2.2 纸品与办公消耗品类（复印纸 / 收银纸 / 标签纸 / 文具）

| 平台 | 规格包装 | 总价 | 折合单包均价 | 专票支持 | 购买链接 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **京东** | A4 70g 5包箱装 | ¥92.5 | **¥18.5 / 包** | 是 | [查看详情](url) |

**单价换算规则（强制）**：
- 只有纸品/文具类（云端返回 `unit_calculation` 非空）才有 `items[].unit_price`；
  整机与耗材类该项为 `null`，属正常，不要自行计算。
- 折算结果**一律以云端为准**（`unit`、`basis`、`basis_note`、`total_price`、`candidates`），
  **不得用标题里的数字心算覆盖云端结果**。
- `basis` 取值与应对：

| `basis` | 含义 | 输出要求 |
| :--- | :--- | :--- |
| `box` | 按整箱折算 | 单价栏正常展示，备注写明"整箱 N 包" |
| `multi_pack` | 按 N 件装折算 | 单价栏正常展示，备注写明件数 |
| `sheet_count` | 按总张数折合包数 | 单价栏正常展示，备注写明张数与折合包数 |
| `single_pack` | 单包/单件价 | 单价即总价 |
| `per_sheet` | 不足一包，按张折算 | 单位写"张"，不要换算成"包" |
| `basis_unknown` | 标题未标注规格 | **只展示总价，单价栏写"规格未标注，无法折算"** |
| `ambiguous` | 标题规格自相矛盾 | **不得替用户挑一个数**：展示 `basis_note` 原文，并把 `candidates` 各项并列列出（"若为单包 ¥X / 若为整箱 ¥Y"），提示"请以下单页面结算为准" |
| `no_price` | 无有效价格 | 该行不参与比价 |

- 云端的 `ambiguous` 判定来自标题里"单包 500 张"与"整箱 5 包"这类同时出现的矛盾表述，
  这是电商标题的常态。**遇到 `ambiguous` 时严禁二选一**，必须如实并列两种可能，
  否则会给出一个精确但错误的单价。
- 不同规格（单包 vs 整箱）**必须分行列出**；跨规格比较时只比较 `unit_price`，并在结论里
  说明"按折合单价比较"。
- 彩色纸常见 100 张/包、收银纸按卷、标签纸按张、文具按支/个，单位以云端返回的 `unit` 为准。

> 单位换算对照（云端 `unit_calculation` 字段）：
> `calculate_per_pack_price` → 包 ｜ `calculate_per_roll_price` → 卷
> `calculate_per_label_price` → 张 ｜ `calculate_per_piece_price` → 个

## 3. 属性与供应类型识别（必须显式标注）

云端已对每条商品做标题解析，结果在 `items[].attributes`。渲染时按下表处理：

| 字段 | 取值 | 输出要求 |
| :--- | :--- | :--- |
| `supply_type` | `原装` | 单独分区展示，标注"原装正品" |
| `supply_type` | `第三方兼容` | 单独分区展示，标注"兼容/适用款" |
| `supply_type` | `原装(标题含适用词)` | 标题同时含"原装"与"适用"，**必须提示"标题表述矛盾，请下单前确认"** |
| `supply_type` | `未标注` | 写"供应类型未标注"，不得默认按原装处理 |
| `model_code` | 型号 | 与用户设备型号核对，不一致时提示"型号与设备不匹配，可能不通用" |
| `gram_weight` / `paper_size` | 纸品规格 | 与用户需求核对，不一致时明确说明 |
| `pack_options` | 包装数量候选 | 有多个取值时说明"标题含多种包装说法，下单前请核对" |

**原装与兼容严禁混价比较**。二者必须分栏或分行，并各自给出最低价，不得写"某耗材最低 ¥X"而掩盖其是第三方兼容品。

## 4. 渠道覆盖与异常处理

- 响应"哪里买最便宜""全网比价"时，必须列出**实际查询过的渠道**。
- 每条 `queries[]` 都有 `status` 字段，逐条说明：
  - `OK` → 有结果，正常渲染。
  - `NO_RESULTS` → "X 平台未检索到相关现货/记录"。
  - `UPSTREAM_ERROR` → "X 平台接口调用异常（原因），本次未覆盖"。
- **未授权渠道**：`detail` 返回的 `warnings` 中若提示"接口可能未授权绑定"，必须如实说明
  "【X 平台】接口未授权绑定，暂时无法提取直达购买链接"，并退守展示可获取链接的平台，
  同时提示"由于部分渠道未授权，本次比价结果仅覆盖部分平台"。
- **异常低价**：远低于正常市场价时提示"价格偏低，请注意核对是否为翻新、二手、非原装或规格不符"。
- **结论边界**：所有主渠道均有数据时才能说"在本次查询到的记录中最低为 ¥X（平台/店铺）"；
  有渠道缺失时必须补"未覆盖 X 渠道，结果仅供参考"。**严禁使用"全网最低"这类无覆盖保证的表述。**

## 5. 链接与数据绑定铁律

- 表格每一行的 **平台、店铺、价格、规格、goodsId、购买链接** 必须来自同一条 `search` 记录
  及其对应 `detail` 结果。严禁把 A 记录的价格与 B 记录的链接拼成一行。
- 购买链接只使用该行 `goodsId` + `source` 调 `detail` 得到的 `data.buy_url`。
  没有拿到链接的写"未获取"，**不得臆造或复用其他商品的链接**。
- `coupon_code`（淘口令）原样照抄，不要改写格式或补空格。
- `goodsId` 长数字原样复制，不得四舍五入或省略。
- 价格时效性：统一标注"以平台页面结算为准"。
