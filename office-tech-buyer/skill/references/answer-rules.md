# 办公设备易采买 —— 答案输出与渲染规则

交付任何办公设备/耗材比价结论前，必须按本文件逐项核对。

---

## 0. 处理流程（先做什么）

1. 调用 `uv run scripts/main.py search --source=0 --keyword='{关键词}'` 搜主设备。
2. **先读返回 JSON 顶层的 `matched` 字段**：
   - `matched: true` → 云端已命中映射表，`queries` 中已包含主设备 + 耗材/配件结果，直接渲染。
   - `matched: false` → 按第 1 节用「设备型号 + 耗材类别词」再搜一轮，再合并渲染。
3. **读顶层 `channels_covered` 决定措辞**：它列出本次**实际**拿到数据的渠道。
   不要依据 `--source=0` 就写「已覆盖全部平台」（见第 4 节）。
4. 对要写进表格的每一行商品，调用 `detail` 获取真实购买链接与专票/质保信息。
5. 按第 2~4 节选择对应表格模板输出，并附第 6 节数据来源声明。

---

## 1. 🤖 客户端宿主 AI 智能匹配兜底逻辑

当 `search` 返回的 JSON 顶层包含 `"matched": false`（云端静态字典未命中该设备的耗材/配件）时，按以下三步处理。**兜底靠搜，不靠猜**：用「设备型号 + 耗材类别词」去搜，让电商标题告诉你这台机器实际在卖什么耗材。

### 1.1 用「设备型号 + 耗材类别词」检索耗材

把用户给的设备型号和**一个**耗材类别词拼成第二个搜索关键词。类别词对照：

| 设备类型 | 类别词 | 示例 |
| :--- | :--- | :--- |
| 打印机 / 一体机 / 复合机 | 墨盒、碳粉盒、硒鼓、墨水、色带、废粉盒 | 「惠普 DeskJet 2720」→ 关键词 `惠普 DeskJet 2720 墨盒` |
| 服务器 | 内存、硬盘托架、电源、散热风扇 | 「浪潮 NF5280M5」→ 关键词 `浪潮 NF5280M5 2.5寸 硬盘托架` |
| 台式机 / 微型机 / 笔记本 | 内存、固态硬盘、电源适配器 | 「联想 M730q」→ 关键词 `联想 M730q 内存` |
| 显示器 | VESA 支架、视频线、电源适配器 | 「戴尔 U2422H」→ 关键词 `戴尔 U2422H VESA 支架` |
| 标签 / 票据打印机 | 标签纸、碳带、收银纸 | 「佳博 GP-3120TU」→ 关键词 `佳博 GP-3120TU 标签纸` |

选词的几条规矩：

- **一次只加一个类别词**。先搜「墨盒」，没结果再换「碳粉盒」「硒鼓」；多个类别词堆在
  一起会显著压低召回。
- **不要把型号代码塞进关键词**。耗材型号是**搜出来的结果**，不是推断出来的输入：
  推测错型号会把整轮结果带偏，比搜不到更糟。类别词只依据「这台机器消耗什么」来选——
  激光机烧碳粉、喷墨机喷墨水、针式机换色带、标签机吃标签纸与碳带。
- **不确定就说不确定**。换了几个类别词仍搜不到时，明确告知"该设备的耗材未检索到，
  建议以机身标签/说明书型号为准"，不得凭记忆给一个型号。
- **不把主设备结果与耗材结果混为一行**。

### 1.2 二次查询

```shell
uv run scripts/main.py search --source=0 --keyword='奔图 P2200 碳粉盒'
```

这一轮结果通常原装款与第三方兼容款混在一起，**直接按每行的 `attributes` 区分即可，
不必分开搜**。供应类型判定看两个字段：

| 字段 | 含义 | 用法 |
| :--- | :--- | :--- |
| `attributes.supply_type` | 标题文本信号：`原装` / `第三方兼容` / `原装(标题含适用词)` / `未标注` | 分区的**唯一**依据 |
| `attributes.supply_tier` | 更保守的旁路判断：`oem_likely` / `compatible` / `unknown` | 用来提示「标称原装但可疑」 |

**`queries[].kind` 不是供应类型判定**。同名查询里会同时混着原装与兼容两款，
`kind` 只说明「这条查询在搜什么」（`primary` / `consumable` / `accessory` / `variant`），
绝不可以在回答里写「本区块为原装耗材」。

关于 `supply_tier`：`supply_type` 只看标题里出现了哪类词，所以「惠普 88A 碳粉盒 原装
再生 得力388AXT」这类标题也会被判成「原装」——实测「惠普 88A 碳粉盒 原装」上游
52 条里 `oem_likely` 只有 2 条（¥529 / ¥1009），`compatible` 47 条（最低 ¥5.0、
中位 ¥28.0）；「联想 LT2451 粉盒 原装」48 条里 `oem_likely` 4 条（¥279–365）、
`compatible` 28 条（¥12.6 起）。真正的原装 CC388A 售价在 ¥300~1000。
`supply_tier = oem_likely` 要求标题同时具备型号与正式原厂前缀（如「惠普(HP)」），
命中它才值得按原装报价；`unknown` 表示无法判断，照 `supply_type` 处理。

只有当某一边确实为空时才各补一轮（不加后缀，见下）：

```shell
uv run scripts/main.py search --source=0 --keyword='奔图 P2200 碳粉盒'
```

> **不要再加「原装」「适用」后缀**。上游对这两个词不做筛选：加「原装」的那一轮
> 返回的仍是兼容品为主的混合结果，等于白占一条查询配额。要分开就在客户端按
> `attributes.supply_type` 分区。

结果里的 `attributes.model_code` 就是这台机器实际在售的耗材型号：
- 若它在一批标题中一致出现（如都写 `CC388A`），可写入耗材表格的型号列；
- 若各条标题的型号互不相同（电商常把同系列通用号写在一起），**照抄标题原文并注明
  "请与机身标签核对"，不要替用户挑一个**。

云端首次返回的 JSON 中还有 `hint` 字段，按其中提示执行即可。

### 1.3 合并展示

将**云端第一次返回的主设备比价结果**与**第二次查询到的耗材/配件比价结果**整合为两份表格：
主设备表格 + 「配套耗材/扩展配件推荐」区块，并在区块前注明
"⚠️ 该耗材由「设备型号 + 类别词」搜索结果得出，未逐条核对与你机型的通用性，下单前请核对机身标签或咨询客服"。

## 2. 📊 结构化 Markdown 输出格式

### 2.1 设备与整机类（电脑 / 服务器 / 打印机 / 显示器 / 人体工学椅）

| 平台 | 店铺类型 | 价格 | 专票/质保 | 核心特征/备注 | 购买链接 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **京东** | 自营官方 | ¥1,099 | 支持专票 / 1年上门 | 次日达 / 晒单送配件 | [查看详情](url) |
| **天猫** | 品牌旗舰店 | ¥1,049 | 支持专票 / 1年联保 | 赠电缆 / 现货 | [查看详情](url) |

字段取值规则：
- **平台**：取 `platform`（由 `source` 映射：1→淘宝/天猫，2→京东，3→拼多多…）。
- **店铺类型**：从 `shopName` 判断——含"自营""官方旗舰店""专卖店""专营店"等字样时按实际标注，否则写"第三方卖家"。
- **价格**：取 `actualPrice`（券后到手参考价）。若 `coupon_desc` 非空，在该行备注补「原价 ¥X，券后 ¥Y」。
  - **价格优先级**：该行若已调过 `detail`，以 `detail` 返回的 `data.actual_price` 为准
    （详情页比搜索列表更新，实测同一 goodsId 在两次请求间会变动，如 20.92→18.83）。
  - 未调 `detail` 的行，在备注补一句"价格未经详情页复核"，不要声称是实时价。
- **专票/质保**：见下方「专票与质保的可得性」，只能引用 `detail` 返回的
  `data.invoice.supported` 与 `data.warranty.text`。
  - `supported: true` → "支持专票"；`false` → "不支持专票"；`null` → "专票未标注"。
  - 质保字段为"未标注"时，表格中照写"质保未标注"，不得自行推断 1 年/3 年。

> ⚠️ **专票与质保的可得性**：上游详情接口**不提供开票资质与质保字段**——实测扫描
> 全部 69~70 个返回字段（京东/拼多多/天猫）都找不到"发票/专票/质保/保修/联保/三包"
> 信号。`detail` 响应顶层的 `invoice_data_available: false` 就是这个事实的机器可读
> 声明。**看到它为 false 时，整列写一次"平台未提供开票信息，请咨询客服"即可，
> 不要逐行写"专票未标注"**——那会让用户以为是我们没查到，而不是数据源没有。
> 只有当 `invoice_data_available` 为 true 时才逐行区分支持/不支持。

💡 **配套耗材/扩展配件推荐**（`matched: true` 时来自 `queries` 中 `kind` 为
`consumable` / `accessory` 的查询结果，**按 `label`（即耗材型号）分别成行**；
`matched: false` 时来自第 1 节按「设备型号 + 类别词」补搜的结果）：

* **耗材**：`[label 里的型号]` `[supply_type]` ¥XX（店铺 / 平台）
* **扩展配件**：`[配件名]` ¥XX（店铺 / 平台）

**必须按 `attributes.supply_type` 分区**——同一条 `consumable` 查询里原装款与兼容款
是混在一起的，把两者拼成「某耗材最低 ¥XX」会掩盖它是第三方品。
鼓粉分离的机型会返回两条 `consumable` 查询（如 `兄弟 TN-2325 粉盒` 与
`兄弟 DR-2350 硒鼓`），**它们是两种不同的耗材，必须分开列**，不要合并成一行。

服务器配件额外读 `attributes.spec_match`：`verdict` 为 `conflict` 时提示
"标题规格为 X，与你的机型要求 Y 不符，请核对"；为 `unknown` 时提示"规格未标注，
请核对"。**不要因为 `conflict` 就丢弃该行**——那会让你漏掉真实在售的商品。

推荐区块必须以"仅列出本次查询到的记录，未覆盖渠道不代表无更低价格"收口。

### 2.2 纸品与办公消耗品类（复印纸 / 收银纸 / 标签纸 / 文具）

| 平台 | 规格包装 | 总价 | 折合单包均价 | 专票支持 | 购买链接 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **京东** | A4 70g 5包箱装 | ¥92.5 | **¥18.5 / 包** | 是 | [查看详情](url) |

**单价换算规则（强制）**：
- 只有纸品/文具类（云端返回 `unit_calculation` 非空）才有 `items[].unit_price`；
  整机与耗材类该项为 `null`，属正常，不要自行计算。
- 折算结果**一律以云端为准**（`unit`、`basis`、`basis_note`、`total_price`、`candidates`），
  **不得用标题里的数字心算覆盖云端结果**。
- `basis` 取值与应对：

| `basis` | 含义 | 输出要求 |
| :--- | :--- | :--- |
| `box` | 按整箱折算 | 单价栏正常展示，备注写明"整箱 N 包" |
| `multi_pack` | 按 N 件装折算 | 单价栏正常展示，备注写明件数 |
| `sheet_count` | 按总张数折合包数 | 单价栏正常展示，备注写明张数与折合包数 |
| `single_pack` | 单包/单件价 | 单价即总价 |
| `per_sheet` | 不足一包，按张折算 | 单位写"张"，不要换算成"包" |
| `basis_unknown` | 标题未标注规格 | **只展示总价，单价栏写"规格未标注，无法折算"** |
| `ambiguous` | 标题规格自相矛盾 | **不得替用户挑一个数**：展示 `basis_note` 原文，并把 `candidates` 各项并列列出（"若为单包 ¥X / 若为整箱 ¥Y"），提示"请以下单页面结算为准" |
| `no_price` | 无有效价格 | 该行不参与比价 |

- 云端的 `ambiguous` 判定来自标题里"单包 500 张"与"整箱 5 包"这类同时出现的矛盾表述，
  这是电商标题的常态。**遇到 `ambiguous` 时严禁二选一**，必须如实并列两种可能，
  否则会给出一个精确但错误的单价。
- 不同规格（单包 vs 整箱）**必须分行列出**；跨规格比较时只比较 `unit_price`，并在结论里
  说明"按折合单价比较"。
- 彩色纸常见 100 张/包、收银纸按卷、标签纸按张、文具按支/个，单位以云端返回的 `unit` 为准。

> 单位换算对照（云端 `unit_calculation` 字段）：
> `calculate_per_pack_price` → 包 ｜ `calculate_per_roll_price` → 卷
> `calculate_per_label_price` → 张 ｜ `calculate_per_piece_price` → 个


### 2.3 严禁行为（对2.1和2.2都适用）
1. 严禁删除表格中的【购买链接】列！
2. 严禁将购买链接单独写在表格下方！
3. 表格内必须使用 `[查看详情](真实url)` 格式，不得直接粘贴原始长链接。

### 2.4 交付前机器自检（强制）

把渲染好的回答**原样**喂给自检脚本，退出码非 0 就说明链接没写进表格，必须重新生成，
不得把这份回答交给用户：

```shell
# 回答已落盘时（推荐）
uv run scripts/check_answer.py --file /tmp/answer.md

# 直接从标准输入
cat /tmp/answer.md | uv run scripts/check_answer.py

# 临时内联（注意引号转义）
uv run scripts/check_answer.py --text '……回答原文……'
```

脚本输出的 JSON 里 `violations` 逐条给出违规行号与原因，`instruction` 是可直接照做的
重写指令。退出码：`0` 通过；`1` 有必须修正项（**必须重新生成**）；`2` 输入有问题。

覆盖的走样形态：整列【购买链接】被删掉；该列为空、写 `-`/`url` 等占位符、或直接粘裸
长链接；链接或淘口令被挪到表格下方、回答末尾、另起一段的清单里。
数据来源声明那一行是唯一允许出现在表格外的带链接行。

## 3. 属性与供应类型识别（必须显式标注）

云端已对每条商品做标题解析，结果在 `items[].attributes`。渲染时按下表处理：

| 字段 | 取值 | 输出要求 |
| :--- | :--- | :--- |
| `supply_type` | `原装` | 单独分区展示，标注"原装正品" |
| `supply_type` | `第三方兼容` | 单独分区展示，标注"兼容/适用款" |
| `supply_type` | `原装(标题含适用词)` | 标题同时含"原装"与"适用"，**必须提示"标题表述矛盾，请下单前确认"** |
| `supply_type` | `未标注` | 写"供应类型未标注"，不得默认按原装处理 |
| `supply_tier` | `oem_likely` | 标题含正式原厂前缀（如「惠普(HP)」）且有型号，可按原装报价 |
| `supply_tier` | `compatible` | 标题含适用/兼容/通用/代用/平替/国产等词，按兼容品处理 |
| `supply_tier` | `unknown` | 无法判断，照 `supply_type` 处理，**不得当作原装确认** |
| `model_code` | 型号 | 与用户设备型号核对，不一致时提示"型号与设备不匹配，可能不通用" |
| `spec_match.verdict` | `conflict` | 标题规格与机型要求同族不同值，**提示核对但保留该行** |
| `gram_weight` / `paper_size` | 纸品规格 | 与用户需求核对，不一致时明确说明 |
| `pack_options` | 包装数量候选 | 有多个取值时说明"标题含多种包装说法，下单前请核对" |

**`supply_type` 是文本信号，不是原装判定**。它只看标题里出现了哪类词，所以
「惠普 88A 碳粉盒 原装 再生 得力388AXT」会被判成「原装」——实测「惠普 88A 碳粉盒
原装」上游 52 条里 `oem_likely` 只有 2 条（¥529 / ¥1009），`compatible` 47 条
（最低 ¥5.0、中位 ¥28.0）；真正的原装 CC388A 在 ¥300~1000。
分区照 `supply_type` 走（它是稳定契约），但**推荐原装款时以 `supply_tier = oem_likely`
为准**；只有 `supply_type = 原装` 而 `supply_tier = unknown` 的行，备注补一句
"标题标注原装但无原厂标识，请核对"。

**原装与兼容严禁混价比较**。二者必须分栏或分行，并各自给出最低价，不得写"某耗材最低 ¥X"而掩盖其是第三方兼容品。

## 4. 渠道覆盖与异常处理

- 响应"哪里买最便宜""全网比价"时，必须列出**实际查询过的渠道**。
- **覆盖范围一律读响应顶层的 `channels_covered`**，不要从 `--source=0` 推断。
  它列出本次真正拿到数据的渠道（`source` / `platform` / `count`）。实测
  `source=0`（"全部"）只覆盖淘宝/天猫、京东、拼多多三家，苏宁、唯品会、抖音、
  快手一条都没有；单独指定 `source=4/5/7/8` 才各自有货。所以 `--source=0`
  **不等于**"已覆盖全部平台"，严禁据此写"全网覆盖"。
- 每条 `queries[]` 都有 `status` 字段，逐条说明：
  - `OK` → 有结果，正常渲染。
  - `NO_RESULTS` → "X 平台未检索到相关现货/记录"。
  - `UPSTREAM_ERROR` → "X 平台接口调用异常（原因），本次未覆盖"。
- **拿不到购买链接的渠道**：`detail` 返回的 `warnings` 中若提示"接口可能未授权绑定"，
  必须如实说明"【X 平台】未能提取直达购买链接"并带上渠道名，同时说明可能原因是
  接口未授权、商品已下架或不支持转链（**不要一律归因为"未授权"**），
  再退守展示可获取链接的平台。
- **异常低价**：远低于正常市场价时提示"价格偏低，请注意核对是否为翻新、二手、非原装或规格不符"。
- **结论边界**：所有主渠道均有数据时才能说"在本次查询到的记录中最低为 ¥X（平台/店铺）"；
  有渠道缺失时必须补"未覆盖 X 渠道，结果仅供参考"。**严禁使用"全网最低"这类无覆盖保证的表述。**

## 5. 链接与数据绑定铁律

- 表格每一行的 **平台、店铺、价格、规格、goodsId、购买链接** 必须来自同一条 `search` 记录
  及其对应 `detail` 结果。严禁把 A 记录的价格与 B 记录的链接拼成一行。
- 购买链接只使用该行 `goodsId` + `source` 调 `detail` 得到的 `data.buy_url`。
  没有拿到链接的写"未获取"，**不得臆造或复用其他商品的链接**。
- **`goodsId` 用 `search` 给的那个**。`detail` 响应里的 `goodsId` 是**回填的调用参数**；
  上游自己返回的 id 在天猫/京东经常与请求值不同（实测 12 次里 8 次变异），
  所以**不要拿 detail 里看不到的"新 id"去二次查询**，也不要怀疑两者不一致是错误。
- `coupon_code`（淘口令）原样照抄，不要改写格式或补空格。
- `goodsId` 长数字原样复制，不得四舍五入或省略。
- 价格时效性：统一标注"以平台页面结算为准"。
